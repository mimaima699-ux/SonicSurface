# SonicSurface 项目进展与相机接入指南

更新日期：2026-10-28

## 一、项目目标与当前结论

项目基于 SonicSurface 16×16 超声相控阵，用 256 路相位控制在空间形成焦点、声场图案和触觉反馈。当前已具备相位计算、声场仿真预览、串口发送、离线算法对照及手掌跟踪的软件链路。

**相机尚未完成可用于正式跟踪的标定。** 当前 RealSense D405 已能连续读取对齐的彩色与深度画面，但已有的一次三维标定尝试误差超限，仅留下诊断记录，不能作为正式标定。手部跟踪的软件链路与离线测试已经实现，实物闭环效果仍待验证。

## 三、算法和控制链路

### 1. 从目标位置到 256 路相位

阵列位于 X-Z 平面，Y 是离开阵面的高度，单位均为米。对于第 i 个换能器和空间点 P，传播模型计算距离、波数及方向性，得到该通道对 P 的复声压贡献。所有通道相加：

```text
p(P) = Σ_i G_i(P) · exp(jφ_i)
```

`G_i(P)` 是传播系数，`φ_i` 是要发送的相位。单焦点的思路是补偿各阵元到焦点的路程差，使到达焦点的声波同相叠加。涡旋和双阱在聚焦相位上增加方位角或半阵列 π 相移；多焦点则通过迭代反传播，在目标点与阵列之间反复施加幅度和纯相位约束。

FPGA 接收 256 个通道相位，每路量化为 32 档（0～31，32 表示关闭）。串口协议为起始字节 254、256 个相位字节、提交字节 253，波特率 230400。板端固件已包含相位校正，`MyPatterns` 发送原始相位，不应在上位机重复校正。

### 2. 图片与三维图案

默认图片算法是阵列感知 GS：在目标图像平面和 256 路等幅发射阵列之间交替传播，逐步逼近目标亮度。梯度方法再优化笔画均匀度和背景亮斑；直接优化方法从一次反传相位出发，以目标误差为目标函数优化。结果用板卡实际 32 档相位重新评价；离线 MSE、背景亮斑等只是传播模型预测，不能替代声场测量。

多深度图片默认按层生成相位帧并轮流播放，不是同一时刻形成多层图案。杯子和网格模型会抽取稀疏轮廓点，逐点扫描焦点；预览热图是多帧时间平均。现有串口帧率和缺少同步触觉调制，是获得连续 3D 触感的限制。

### 3. 触觉调制与手掌跟踪

`burst`、`hold` 等命令把图案与关闭状态交替提交，实现低频幅度调制；默认跟踪调制频率是 200 Hz。手掌跟踪的软件流程是：

```text
RealSense 彩色画面 → MediaPipe 食指尖像素坐标 (u,v)
         → 对齐深度图反投影 → 相机三维坐标
         → 两层标定得到的刚体变换 → 阵列坐标 (x,y,z)
         → One-Euro 滤波 + 5 mm 重发死区
         → 计算焦点相位 → 串口发送/调制
```

当前版本可根据深度估计指尖高度 `y`，并跟随 X、Y、Z。普通模式默认要求 X/Z 在 ±0.08 m、高度在 0.07～0.20 m；指尖丢失超过 0.5 s、深度无效或越界时，程序请求静默；退出时也会发送关闭帧。真实关断仍取决于串口和硬件状态。

## 四、相机接入教程：从未固定、未标定开始

以下命令在 Windows PowerShell 中、从仓库根目录 `D:\Mima\SonicSurface` 运行。示例使用**本机另一个仓库** `ultrasound_solver/.venv` 的解释器；该虚拟环境不在 GitHub 仓库中。克隆后需自行配置 Python，安装 `numpy`、`scipy`、`matplotlib`、`pillow`、`pyserial`、`opencv-python`、`mediapipe`、`pyrealsense2`，并把下文命令开头的 Python 路径换成自己的解释器。三维标定与跟踪需要 RealSense 彩色和深度流；普通 USB 摄像头可用于预览，但不能代替当前三维标定。第 1～5 步不需要连接超声板卡。

### 第 1 步：固定相机并定义阵列坐标

1. 把 RealSense 固定在稳定支架上，使阵列中心和指尖工作区都在彩色画面及有效深度范围内；相机不必正对阵面，但标定后不能相对阵列移动。
2. 以阵列中心为 `(0,0,0)`，标记阵面内的 `+X`、`+Z`，离阵方向为 `+Y`。不要把画面左右直接当成阵列方向。
3. 用尺子准备 X/Z 各为 `-0.06 / 0 / +0.06 m` 的九个位置，并在每个位置准备指尖离阵面 `0.10 m` 和 `0.15 m` 两层高度，共 18 个采样点。高度量到**食指尖**，不是手掌或相机镜头。
4. 固定照明、分辨率和曝光。相机位置或图像分辨率改变后，重新标定。

### 第 2 步：确认彩色与深度连续出帧

先在 RealSense Viewer 确认彩色和深度流正常，再运行：

```powershell
cd D:\Mima\SonicSurface
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\hand_track.py camtest --realsense --depth
```

查看红圈是否落在食指尖、右侧对齐深度图对应位置是否有有效值。深度为黑色或无法连续出帧时先排查相机、USB 连接和占用，暂不标定。`--pointcloud` 可额外打开三维点云辅助检查，但点云仍是相机坐标。

### 第 3 步：整定画面并确认识别食指尖

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\hand_track.py camtest --realsense --depth --target index_tip
```

在两层高度和九个横向位置检查食指尖检测是否稳定、深度是否有效。画面忽明忽暗时可按 `X` 关闭自动曝光，再用 `W/S` 调曝光；按 `ESC` 将设置保存到本机 `MyPatterns/results/hand_tracking/hand_track_cam.json`。**保存设置后再标定**，标定后不要改分辨率或移动相机。

### 第 4 步：采集两层共 18 个标定点

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\hand_track.py calibrate --realsense --dist 0.10 --height-step 0.05
```

程序按每个 X/Z 位置先 10 cm、再 15 cm 的顺序提示坐标。把**食指尖**放到提示位置，待标记处深度稳定后按空格采样；`r` 重采上一点，`q` 放弃，`V` 切换彩色/深度预览。最好一人摆手、一人操作键盘。

只有 RMS 不超过 10 mm、单点最大误差不超过 20 mm，程序才会把正式结果写入 `MyPatterns/results/hand_tracking/hand_track_calib_3d.json`。超标时会打印各点误差并保存本机诊断文件 `hand_track_calib_3d_diagnostic.json`；检查指尖实际高度和深度值后重采。旧的二维 `hand_track_calib.json` 不能用于当前三维跟踪。

### 第 5 步：不接板卡，验证坐标和丢手响应

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\hand_track.py track --realsense --dry --max-seconds 20
```

把食指尖分别放到中心、四个方向及不同高度，核对画面中的 `x,y,z` 与尺量位置和运动方向。移开手后确认进入 `[off]`；越界时也应静默。按 `q` 或 `Ctrl+C` 退出。此步骤**不连接串口，也不会发射超声**。

若方向或高度不符，检查坐标轴标记、18 点摆放顺序和深度图，再重标。已有的失败诊断只能通过显式 `--experimental` 进入受限实验模式，不能当成正式标定。通过独立验证后再接板卡。

### 第 6 步：单独检查板卡，再做短时间闭环试验

先确认当前串口，示例中的 `COM8` 不是固定设备号：

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\my_patterns.py ports
```

正式三维标定和离线验证通过后，再启动短时间跟踪。首次试验可先用 `focus` 和较低占空比，操作员留在终端旁，随时用 `q` 或 `Ctrl+C` 停止：

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\hand_track.py track --realsense --kind focus --freq 200 --duty 0.3 --max-seconds 20 --port COM8
```

结束后核对程序提示及板卡实际状态；必要时在串口空闲后单独发送 `off`：

```powershell
.\ultrasound_solver\.venv\Scripts\python.exe -X utf8 MyPatterns\my_patterns.py off --port COM8
```

程序的关断机制是软件保护，不等于断电确认。若丢帧、坐标偏移、串口报错或触感位置不对，先停止发射，回到第 3～5 步排查。不要用“有触感”代替坐标和声场位置的验证。

## 五、完成标定的验收记录

建议在首次成功后记录：相机型号与安装照片、分辨率和曝光、相机到阵列的相对位置、两层采样高度、18 点 RMS 和最大误差、中心与边缘的独立检查误差、丢手后静默表现、实物焦点位置和实际 COM 端口。本机标定 JSON 和相机快照不上传 GitHub；相机安装或画面参数改变后重新标定。

当前最近的工作顺序是：**固定相机 → 检查彩色与深度 → 两层 18 点标定 → `--dry` 独立验证 → 板卡闭环实测**。在完成这些步骤之前，相机跟踪仍属于待验证功能。
